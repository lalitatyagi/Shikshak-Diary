## 2. Render (API) — you do this

1. Open [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**.
2. Select repo `lalitatyagi/Shikshak-Diary` → apply `render.yaml`.
3. Set Blueprint secrets (`sync: false`):
   - `DATABASE_URL` — Neon connection string (same as local `apps/api/.env`, or pooled URL)
   - `CORS_ORIGINS` — temporarily `http://localhost:5173` **or** your expected Vercel URL, e.g. `https://shikshak-diary.vercel.app`
4. Wait for deploy. Health: `https://classroom-tracker-api.onrender.com/health`  
   (name comes from `render.yaml`; adjust if Render renames it.)
5. Free tier spins down after idle; first request can take ~30–60s.

`start:deploy` runs `prisma migrate deploy` then starts the server. JWT secrets are auto-generated by the Blueprint (`COOKIE_SAMESITE=none`, `COOKIE_SECURE=true`).

---

## 3. Vercel (web) — you do this

**Option A — Dashboard**

1. [Vercel](https://vercel.com) → **Add New Project** → import `lalitatyagi/Shikshak-Diary`.
2. Framework preset: **Other**. Root directory: repository root (`vercel.json`).
3. Environment variable (Production):
   - `VITE_API_BASE_URL` = `https://<your-render-service>.onrender.com` (no trailing slash)
4. Deploy. Open the site → sign in with the demo teacher.

**Option B — CLI** (from this repo)

```bash
npx vercel login
npx vercel            # link project, set env when prompted or via dashboard
npx vercel --prod
```

Set `VITE_API_BASE_URL` in the Vercel project env before a production build — it is baked in at build time.

---

## 4. Wire CORS (after both URLs exist)

1. Copy the real Vercel origin, e.g. `https://shikshak-diary.vercel.app`.
2. Render → API service → Environment → set `CORS_ORIGINS` to that origin (comma-separate previews if needed).
3. Redeploy / restart the API.
4. Reply with both URLs so README “Live demo” can be filled in.

If login works but refresh fails after ~15 minutes:

- `CORS_ORIGINS` includes the **exact** Vercel origin (https, no trailing slash mismatch)
- `COOKIE_SAMESITE=none` and `COOKIE_SECURE=true` (Blueprint defaults)
- Browser is on HTTPS

## 5. Local check of production cookie settings

```bash
# API
$env:NODE_ENV="production"; $env:COOKIE_SAMESITE="none"; $env:COOKIE_SECURE="true"; $env:CORS_ORIGINS="http://localhost:5173"; npm run dev:api

# Web (separate terminal)
$env:VITE_API_BASE_URL="http://localhost:3001"; npm run dev:web
```

## Why this split

| Piece | Host | Why |
| --- | --- | --- |
| Postgres | Neon | Managed Postgres; already linked; scale-to-zero |
| API | Render | Long-running Node + Prisma; free tier; Blueprint as code |
| Web | Vercel | Static Vite SPA; env `VITE_*` at build time |

Cross-origin cookies need `SameSite=None; Secure` because the SPA and API are on different sites. Locally, Vite’s `/api` proxy stays available when `VITE_API_BASE_URL` is unset.
