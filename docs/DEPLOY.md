# Deploy Classroom Tracker (Step 8)

Stack: **Neon** (Postgres) · **Render** (API) · **Vercel** (web).

## 1. Neon (database)

You already have a Neon project. Confirm:

1. Copy the connection string (prefer the **pooled** URL if Render is serverless-idle; for a long-running Render web service the direct URL is fine).
2. Seed once from your laptop (seed refuses `NODE_ENV=production`):

```bash
# In apps/api/.env — DATABASE_URL points at Neon
# NODE_ENV must NOT be production for this command
npm run db:migrate
npm run db:seed
```

Demo login after seed: `teacher@demo.local` / `Teacher123!`

## 2. Render (API)

1. Push this repo to GitHub (already: `lalitatyagi/Shikshak-Diary`).
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint** → select the repo → apply `render.yaml`.
3. Set these Blueprint secrets (marked `sync: false`):
   - `DATABASE_URL` — Neon URL
   - `CORS_ORIGINS` — your Vercel origin, e.g. `https://classroom-tracker.vercel.app`  
     (add comma-separated preview URLs later if needed)
4. After the first deploy, open `https://<service>.onrender.com/health` — expect `{ "status": "ok", ... }`.
5. Free tier spins down after idle; the first request can take ~30–60s.

`start:deploy` runs `prisma migrate deploy` then starts the server. JWT secrets are auto-generated by the Blueprint.

## 3. Vercel (web)

1. [Vercel](https://vercel.com) → **Add New Project** → import the same GitHub repo.
2. Framework preset: **Other**. Root directory: repository root (uses `vercel.json`).
3. Environment variable:
   - `VITE_API_BASE_URL` = `https://<your-render-service>.onrender.com` (no trailing slash)
4. Deploy. Open the site → sign in with the demo teacher.

If login works but refresh fails after 15 minutes, check:

- API `CORS_ORIGINS` includes the exact Vercel origin
- API `COOKIE_SAMESITE=none` and `COOKIE_SECURE=true` (Blueprint defaults)
- Browser is on HTTPS (required for `SameSite=None`)

## 4. Wire CORS after you know both URLs

Order of operations that avoids chicken-and-egg:

1. Deploy API on Render with `CORS_ORIGINS=http://localhost:5173` temporarily (or your expected Vercel URL).
2. Deploy web on Vercel with `VITE_API_BASE_URL` pointing at Render.
3. Update Render `CORS_ORIGINS` to the real `https://….vercel.app` and redeploy the API.

## 5. Local check of production settings

```bash
# API
NODE_ENV=production COOKIE_SAMESITE=none COOKIE_SECURE=true \
  CORS_ORIGINS=http://localhost:5173 npm run dev:api

# Web (separate terminal)
VITE_API_BASE_URL=http://localhost:3001 npm run dev:web
```

## Why this split

| Piece | Host | Why |
| --- | --- | --- |
| Postgres | Neon | Managed Postgres; already linked; scale-to-zero |
| API | Render | Long-running Node + Prisma; free tier; Blueprint as code |
| Web | Vercel | Static Vite SPA; env `VITE_*` at build time |

Cross-origin cookies need `SameSite=None; Secure` because the SPA and API are on different sites. Locally, Vite’s `/api` proxy stays available when `VITE_API_BASE_URL` is unset; the refresh cookie uses `Path=/` so it is sent on `/api/auth/*`.
